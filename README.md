# EMS GD

ระบบจัดการพลังงาน (Energy Management System) ของเรา เริ่มจากการอ่านและตรวจสอบไฟล์ TOU ที่เครื่องประมวลผลบันทึกไว้แล้ว

## เป้าหมายระยะแรก

- ทดลองอ่านไฟล์ `.tou` จริง โดยคงชื่อไฟล์เดิมเพื่อระบุเดือนและปี
- ตรวจค่า Demand และเลขพลังงานสะสม พร้อมระบุข้อมูลที่ขาดหรือผิดปกติ
- เทียบยอด OnPeak, OffPeak, Holiday และ Maximum Demand กับรายงานจากโปรแกรมเดิม
- เมื่อยืนยันผลกับไฟล์จริงแล้ว จึงเพิ่มการอ่านไฟล์จากโฟลเดอร์บนเครื่องโดยอัตโนมัติ

## สถานะ

มีหน้า Dashboard ของ EMS GD สำหรับดูกราฟ Demand, สัดส่วน TOU, ตารางรายวัน, ข้อมูลดิบ และส่งออกรายงาน CSV แล้ว เปิดพร้อมข้อมูลจำลอง 4 แบบ และเลือกนำเข้าไฟล์ `.tou` ของตัวเองได้ ยังไม่มีตัวอ่านโฟลเดอร์อัตโนมัติใน repository นี้

## เปิด Dashboard บนเครื่อง

```sh
npm run preview
```

เปิด `http://127.0.0.1:8765` หน้าจออยู่ในโฟลเดอร์ `web/` และประมวลผลไฟล์ที่เลือกในเบราว์เซอร์โดยไม่ส่งขึ้นเซิร์ฟเวอร์ ตัวอ่านและคำนวณ TOU เขียนขึ้นใหม่ใน `web/tou-engine.mjs` และตรวจผลกับรายงานต้นแบบครบทั้ง 4 ชุด

ดาวน์โหลดไฟล์ตัวอย่างที่สร้างไว้แล้วได้จาก [`examples/tou/`](examples/tou/) แล้วเลือกไฟล์ `.tou` เข้า [Dashboard_TOU](https://github.com/Satitpae/Dashboard_TOU) โดยคงชื่อไฟล์เดิมไว้ ภายในโฟลเดอร์มี CSV และผลตรวจเทียบประกอบ

## ทดลองด้วยข้อมูลจำลอง

ต้องมี Node.js 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่มเติม

```sh
npm test
npm run generate:sample
```

โปรแกรมสร้างไฟล์ใน `simulated-data/` หรือระบุโฟลเดอร์ปลายทางได้ด้วย `node scripts/generate-tou.mjs <output-directory>`

ไฟล์ทุกชุดเป็นข้อมูลจำลองเดือนกันยายน 2026 พร้อมแถว 00:00 ของวันที่ 1 ตุลาคม แต่ละไฟล์มี 2,881 แถว ขนาด 46,160 bytes ใช้ชื่อไฟล์เดิมเมื่อนำเข้า Dashboard_TOU

| ไฟล์ | การจำลอง |
| --- | --- |
| `SIM_REFERENCE_Sep26.tou` | โหลดคงที่ 10 kW ใช้ตรวจสูตรด้วยค่าที่คำนวณล่วงหน้า |
| `SIM_OFFICE_Sep26.tou` | สำนักงาน: โหลดสูงกลางวันของวันทำงาน ลดลงกลางคืนและวันหยุด |
| `SIM_FACTORY_Sep26.tou` | โรงงาน: มีโหลดตลอดวันและช่วงเดินเครื่องสูง |
| `SIM_ISSUES_Sep26.tou` | สำนักงานที่มีข้อมูลขาด ขอบเวลา TOU หาย มิเตอร์รีเซ็ต และหยุดบันทึกหลังวันที่ 26 เวลา 15:00 |

ไฟล์ `.csv` คู่กันแสดงข้อมูลดิบและป้ายกำกับเหตุการณ์ `manifest.json` เก็บรายละเอียดการจำลองและ SHA-256

ข้อมูลและรายงานในชุดนี้ใช้ทดสอบเท่านั้น ไม่ใช่ข้อมูลมิเตอร์จริง และแต่ละไฟล์เป็นตัวอย่างคนละกรณี ไม่ควรรวมยอดเป็นไซต์เดียว

### ค่าตรวจสอบสำหรับโหลดคงที่ 10 kW

เดือนกันยายนมี 22 วันทำงานและ 8 วันเสาร์–อาทิตย์ ไม่มีวัน Holiday เพิ่มเติมในปฏิทินเดือนนี้ของ Dashboard_TOU

| รายการ | kWh |
| --- | ---: |
| ผลต่างเลขสะสมทั้งเดือน | 7,200 |
| OffPeak ตามรายงานเดิม | 2,417.5 |
| OnPeak ตามรายงานเดิม | 2,860 |
| Holiday ตามรายงานเดิม | 1,920 |
| รวมตามรายงานเดิม | 7,197.5 |

ยอดตามรายงานเดิมต่างจากทั้งเดือน 2.5 kWh เพราะ Dashboard_TOU เริ่มวันแรกที่ 00:15 ตารางตรวจรายวันอยู่ใน `SIM_REFERENCE_Sep26_expected_daily.csv`

รายงานที่ชื่อ `*_dashboard_daily.csv` และ `dashboard-verification.json` ในชุดดาวน์โหลดมาจากการตรวจด้วยโค้ด Dashboard_TOU เดิมโดยไม่แก้สูตร ตัวกำเนิดข้อมูลอย่างเดียวไม่สร้างรายงานตรวจเทียบเหล่านี้ใหม่ ค่า TOTAL ของกรณี ISSUES เป็นเพียงผลรวมส่วนที่คำนวณได้ ต้องอ่านสถานะข้อมูลควบคู่กัน

## รูปแบบข้อมูลที่ตรวจจาก Dashboard_TOU

- ไฟล์ไบนารี TOUReg: header 64 bytes ตามด้วยคู่ Demand / Energy แบบ little-endian float64
- ชื่อไฟล์ลงท้ายด้วยเดือนภาษาอังกฤษและปี เช่น `D01Sep26.tou`
- เวลาอ้างอิงลำดับข้อมูลทุก 15 นาที; Energy เป็นเลขสะสม จึงคำนวณการใช้จากผลต่าง
- ต้องยืนยันหน่วย ตัวคูณมิเตอร์ และวิธีคิด TOU กับไฟล์และรายงานจริงก่อนนำผลไปใช้งาน
